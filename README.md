একটাই সিস্টেম, দুইটা রূপ — **টেলিগ্রাম বট** আর **ওয়েবসাইট**। দুটো একই ডেটাবেজ
ব্যবহার করে, তাই বটে যা করবেন সাইটে ঠিক সেটাই দেখা যাবে — আর সাইটে যা করবেন বটে
সাথে সাথে কার্যকর হবে।

| | কী | কোথায় |
|---|---|---|
| 🤖 | বট — ইউজার এক ট্যাপে ভিডিও পায়, প্রিমিয়াম কেনে, সাপোর্ট করে | `t.me/<yourbot>` |
| 🌐 | পাবলিক সাইট — সব স্টোর, ডিপ-লিংক, সার্চ | `http://host:PORT/` |

**v3-এ নতুন:** এক ট্যাপে সরাসরি ভিডিও ডেলিভারি · শুধু ভিডিও/ছবি গ্রহণ (টেক্সট আর কখনো

(যেমন ১০০ বার, তারপর “লিমিট শেষ”) · স্টোর-ভিত্তিক আলাদা ফোর্স-জয়েন চ্যানেল ·
ডেলিভারির আগে সাবস্ক্রিপশন চেক · মিডিয়া ক্যাশ (forward/delete চক্র ও FloodWait শেষ) ·
ব্রডকাস্ট এখন সত্যিই সবার কাছে পৌঁছায় · নিজে থেকেই মিডিয়া ক্যাশ, সাপ্তাহিক ডাইজেস্ট,
সেলফ-টেস্ট ও লাইভ লগ।

## ⚡ দ্রুত শুরু

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt -r requirements-web.txt

cp config.env.example config.env
nano config.env        # API_ID, API_HASH, BOT_TOKEN, ADMIN_IDS

.venv/bin/python run.py        # ⭐ বট + ওয়েবসাইট একসাথে
```

- শুধু বট: `python bot.py` · শুধু সাইট: `python -m web.dashboard`
- **ব্রডকাস্টের জন্য bot worker চালু থাকা দরকার।** শুধু `python -m web.dashboard` চালালে
  Telegram পাঠানো হয় না; campaign নিরাপদে queued থাকে। Production-এ combined command ব্যবহার করুন।
- হোস্টিং প্যানেল (CodeNest / Render / Railway): start command **`python run.py`**,
  পোর্ট নিজে থেকেই `$PORT` ধরে নেয়।
- বট কানেক্ট না হলেও **সাইট চালু থাকে**; বট নিজে থেকেই আবার কানেক্ট হয়।
- ডেমো ডেটা দেখতে: `DB_FILE=preview.sqlite3 .venv/bin/python tools/seed_demo.py`
- বিস্তারিত ডিপ্লয়: **[DEPLOY.md](DEPLOY.md)** · env ভেরিয়েবল: **[ENV.md](ENV.md)**

## 🙂 ইউজারের দিকটা ইচ্ছে করে সহজ রাখা হয়েছে

- স্টোর লিংকে ক্লিক → **সোজা ভিডিও**। মাঝখানে বাটনের পর বাটন নেই, এক ধাপেই কাজ শেষ।
- দরকার হলে আগে **একটাই** মেসেজ আসে: যেসব চ্যানেল জয়েন করা লাগবে + একটা
  “✅ আমি জয়েন করেছি” বাটন → জয়েন করা থাকলে সাথে সাথে ভিডিও চলে যায়।
- নিচে **স্থায়ী বাটন**: `🏠 Store list` · `🔍 Search` · `💎 My access` · `🆘 Help`
  — কোনো কমান্ড মুখস্থ লাগে না।
- স্টোর লিস্ট না এলে বট চুপ করে থাকে না: retry করে, শেষে প্লেইন মেসেজ + ফিরে আসার পথ।
- `/menu` — যেকোনো সময় মেনু · `/cancel` — যেকোনো কাজ বাতিল · 🌐 বাংলা/English।
- পাবলিক সাইটে **প্রিমিয়াম স্টোরের ফাইলের নাম কখনো দেখা যায় না** — শুধু “প্রিমিয়াম”।

## 🔒 ডেলিভারির নিয়ম (v3-এ পুরো বদলেছে)

```
ইউজার লিংকে ক্লিক (/start f12 · স্টোর লিংক · লিমিটেড লিংক)
        │
        ├── অ্যাক্সেস নেই?           → প্রিমিয়াম পেজ + কিনুন/যোগাযোগ
        │
        ├── ফোর্স-জয়েন চেক  ← ভিডিও দেওয়ার *আগে* হয়
        │        │
        │        ├── জয়েন করেনি   → এক মেসেজ: চ্যানেল বাটন + “✅ আমি জয়েন করেছি”
        │        │                  (এখানেই ইউজার আটকে থাকে, বাকি সব বন্ধ)
        │        └── জয়েন করেছে   → ⬇️
        │
        └── ভিডিও সরাসরি চলে যায় (এক ট্যাপ, extra বাটন নেই)
```

- চ্যানেল আটা **স্টোর-ভিত্তিক** হতে পারে: স্টোর #১-এ `@cinema_backup`,
  স্টোর #২-এ অন্য চ্যানেল — ডিফল্ট চ্যানেলের সাথে এগুলোও যোগ হয়।
- টেলিগ্রাম কিছু যাচাই করতে না পারলে ইউজারকে **আটকানো হয় না** (fail-open) —
  চেকিংয়ের ঝামেলায় পেইং কাস্টমার আটকে যাওয়া অনেক বড় ক্ষতি।

## 🛠️ অ্যাডমিন প্যানেল (`/admin`) — সব কাজ এক জায়গায়

Public storefront-এ কোনো management/admin entry নেই; সরাসরি `/admin` খুললেই password form আসে। Login password `web/dashboard.py`-তে fixed source constant—এটি public repository-তে থাকলে যে কেউ পড়তে পারে। Password-only sign-in, HttpOnly cookie ও rate limiting আছে; এই source-level setup production-এ ঝুঁকিপূর্ণ, তাই repository private রাখুন বা secret store ব্যবহার করুন।

| পেজ | কী করে |
|---|---|
| 📊 `/admin` | ইউজার, ফাইল, স্টোর, ভিউ, আয়, পেন্ডিং অর্ডার, খোলা টিকেট, সাম্প্রতিক ব্রডকাস্ট |
| 📢 `/admin/broadcast` | ব্রডকাস্ট স্টুডিও — তৈরি, টেস্ট, শিডিউল, লাইভ প্রোগ্রেস, রিট্রাই, স্টপ |
| 📡 `/admin/channels` | চ্যানেল ম্যানেজমেন্ট + `/admin/channels/compose` — **ইনলাইন বাটনসহ চ্যানেল পোস্ট** |
| 📲 `/admin/session` | ওয়েব থেকে Telegram phone/code/2FA দিয়ে নিজের session connect বা disconnect; session string কখনো পেজে দেখায় না |
| 📊 `/admin/analytics` | প্রতি-ইউজার ও প্রতি-স্টোর অ্যানালিটিক্স, ফানেল, জনপ্রিয় ফাইল |
| 🔗 `/admin/links` | লিমিটেড/আনলিমিটেড লিংক তৈরি, কতবার ব্যবহৃত, বাকি কত, রিভোক |
| 🏪 `/admin/stores` → 🛠 | ওয়েব থেকে Store তৈরি/এডিট, ফাইল, access, analytics; চাইলে session দিয়ে প্রতি Store-এর নিজস্ব publish channel তৈরি ও নতুন ভিডিও auto-post |
| 🗂 `/admin/files` | সব স্টোরে সার্চ, ক্যাশ টুল, ডুপ্লিকেট পরিষ্কার, প্রতি ফাইলে 📢 ব্রডকাস্ট |
| 👥 `/admin/users` → ক্লিক | প্রতি ইউজারের পূর্ণ প্রোফাইল (নিচে দেখুন) |
| 🧾 `/admin/orders` | এক ক্লিকে ✅ অ্যাপ্রুভ / ❌ রিজেক্ট (অ্যাপ্রুভ = সাথে সাথে অ্যাক্সেস + নোটিফিকেশন) |
| 🩺 `/admin/self-test` | **সেলফ-টেস্ট** — ডেটাবেজ, বট, সেশন, মিডিয়া ক্যাশ, চ্যানেল, ব্রডকাস্ট কিউ, FloodWait |

## 📊 অ্যানালিটিক্স — “কে কোথায় ক্লিক করল, কে কী দেখল”

প্রতিটি অর্থবহ কাজ `events` টেবিলে জমা হয় (`start`, `open_store`, `view_file`,
`deliver`, `join_block`, `join_click`, `limit_block`, `pay_start`, `paid`,
`search`, `add_file`, `channel_post`, `broadcast_start`, `scan` …)।

**প্রতি ইউজার** (`/admin/users/<id>`, বটে `📊 Analytics` → ইউজার):
ইউজারনেম, জয়েন/শেষ দেখা, কোন স্টোরে কতবার ঢুকল, **কোন কোন ভিডিও দেখল (কতবার,
সর্বশেষ কখন)**, সবচেয়ে বেশি সার্চ করা শব্দ, অ্যাক্সেস, অর্ডার, সাপোর্ট টিকিট,
পুরো ইভেন্ট-টাইমলাইন — আর ড্যাশবোর্ড থেকে সোজা মেসেজ/ব্যান করার বাটন।

**প্রতি স্টোর** (`/admin/analytics/store/<id>`, বটে `📊 এই স্টোরের স্ট্যাটস`):
**ফানেল** — কতজন এসেছে → কতজন জয়েন করেছে → কতজন ভিডিও দেখেছে → কতজন কিনেছে;
**কোন ভিডিও কতজন ইউনিক ইউজার দেখেছে** (views/unique/মোট পাঠানো/শেষ কখন);
**কে কী দেখেছে** (প্রতি ইউজার কতটি ভিন্ন ভিডিও); সাম্প্রতিক ইভেন্ট।

**প্রতি ফাইল** (`/admin/analytics/file/<id>`): যারা ফাইলটি পেয়েছে (কতবার, শেষ কখন)
আর **যারা জয়েন করতে পারেনি** — কতবার চেষ্টা করেছে (ফলো-আপের জন্য একদম দরকারি)।

## 📡 চ্যানেল ম্যানেজমেন্ট + চ্যানেল পোস্ট

- **চ্যানেল যোগ করুন যেকোনো রেফারেন্স দিয়ে:** `@username`, `https://t.me/…`,
  `https://t.me/+ইনভাইট`, `-100…` আইডি — অথবা চ্যানেলের যেকোনো পোস্ট **forward** করুন।
- **স্কোপ:** 🌍 সব স্টোরে (ফোর্স-জয়েন + ক্যাশ) অথবা একটা নির্দিষ্ট স্টোরের জন্য।
- প্রতি চ্যানেলে: 🔎 চেক (নাম + সদস্য সংখ্যা), 🚫 বন্ধ/চালু, 🗑 ডিলিট।
- **চ্যানেল পোস্ট (delivery):** মেসেজ + একাধিক ফাইল + **ইনলাইন URL বাটন**।
  বাটনের সিনট্যাক্স — প্রতি লাইনে একটা, `লেবেল | লিংক`; একই লাইনে `&&` দিলে পাশাপাশি:

  ```
  📢 জয়েন করুন | https://t.me/mychannel
  🟢 স্টোর খুলুন | https://t.me/mybots?start=সিনেমা_হাউস && 💬 অ্যাডমিন | https://t.me/myid
  ```

- **লিমিটেড লিংক মোড:** চ্যানেলে ভিডিও না দিয়ে শুধু একটা বাটন দেওয়া যায় — যেমন
  “🔓 ভিডিও নিন (১০০ বার)”; তারপর ঠিক ১০০ ক্লিকের পর ইউজারকে বলা হয়
  “লিমিট শেষ — অ্যাক্সেস দেওয়া হবে না”।

  (ওয়েব `/admin/files` + বটের ফাইল ম্যানেজার), অথবা স্টুডিওতে ফাইল বাছুন।

- **ইনলাইন বাটন** প্রতিটি মেসেজে যোগ হয় — ব্রডকাস্ট ফর্মের বাটন ফিল্ডে লিখুন,
  আর **“🟢 অনলাইন — স্টোর খুলুন”** বাটনটা টিক দিয়ে চালু/বন্ধ (প্রতি ক্যাম্পেইনে আলাদা)।

- 🧪 টেস্ট পাঠানো (আসল ভুল ধরা পড়ে এখানেই) · 📅 শিডিউল · ⏹ মাঝপথে স্টপ ·
  🔁 শুধু ফেল/ব্লক করা ইউজারদের রিট্রাই · ৩ সেকেন্ডে লাইভ প্রোগ্রেস।

  জন্য forward ব্যর্থ হত। এখন প্রতিটি ফাইল **একবার ক্যাশ** হয়, তারপর বট নিজেই হাজার
  ইউজারকে পাঠায়। তাই ব্রডকাস্ট সত্যিই পৌঁছায় (টেস্ট পাঠানোর সময়ই ভুল ধরাও পড়ে)।

## 🖼️ কনটেন্ট নিয়ম — শুধু ভিডিও/ছবি, টেক্সট কখনো নয়

- **সেভ হয়:** `Video` ✅ · `Photo` ✅ (প্যানেল থেকে চাইলে প্রসারিত করা যায় —
  `CONTENT_MEDIA_KINDS`)।
- **কখনো সেভ হয় না:** টেক্সট, লিংক প্রিভিউসহ মেসেজ, স্টিকার/GIF, অডিও, ভয়েস,
  ডকুমেন্ট, পোল — বরং বট স্পষ্ট করে বলে দেয় কিছুই সেভ হয়নি।
- ভিডিও/ছবি **পাঠালেই** সেভ হয় (forward করলেও), নাম হয় ক্যাপশন থেকে —
  ক্যাপশন না থাকলে `Video 3` জাতীয় নাম। ডুপ্লিকেট চারবার সেভ হয় না।
- **“যেকোনো টেক্সট দিলে বারে বারে সেভ হইতেছে”** — আসল কারণ ছিল লিংক প্রিভিউ:
  টেলিগ্রাম লিংক-সহ টেক্সটেও `media` সেট করে, তাই পুরোনো কোড প্রতিবার নতুন আইটেম
  বানাত। এখন `MessageMediaWebPage` আলাদা করে চেনা হয় এবং কিছুই লেখা হয় না।
- স্ক্যানার (চ্যানেল থেকে অটো-সংগ্রহ)-ও একই নিয়ম মানে — শুধু ভিডিও/ছবি।

## 📥 “ফাইল বোর্ডে ফরওয়ার্ড হয়ে ডিলিট হচ্ছিল” + FloodWait — সমাধান

আগে বট পড়তে না পারলে সেশন দিয়ে ফাইলটা বটের DM-এ forward করে, পাঠিয়ে, **কপিটা
ডিলিট** করে দিত। কয়েকজন একসাথে ক্লিক করলে একই ভিডিও বারবার forward-delete হত →
FloodWait, কেউ ফাইল পেত না।

এখন **মিডিয়া ক্যাশ** (`app/services/media_cache.py`):

1. যে ফাইল বট নিজে পড়তে পারে, সরাসরি পাঠায় (কিছুই কপি করে না)।
2. না পারলে **একবারই** কপি করা হয় — লক্ষ্য `STORAGE_CHANNEL` (প্যানেলে সেট করা),
   না থাকলে স্টোর-মালিকের DM — এবং `files.mirror_chat/mirror_msg`-এ মনে রাখা হয়।
3. এরপর প্রতিটি ক্লিক, সার্চ, লিমিটেড লিংক, ব্রডকাস্ট = **বটের সাধারণ send**:
   সেশন ট্রাফিক নেই, forward নেই, ডিলিট নেই, FloodWait নেই।
4. বড় ফাইল চাইলে ranged/chunked ডাউনলোড করে re-upload হয় (restricted/forward-protected
   সোর্সেও কাজ করে), `MIRROR_MAX_MB` সীমা মানে।
5. ব্যাকগ্রাউন্ড লুপ (`mirror_loop`) নিজে থেকেই ক্যাশ গরম রাখে; প্যানেলে
   **📥 সব ফাইল ক্যাশ করুন** বাটনও আছে।

- দৈনিক অটো-ব্যাকআপ (`BACKUP_DIR`, `KEEP_BACKUPS`) + প্যানেল থেকে ম্যানুয়ালি।
- প্যানেল → 📥 Export: SQLite, JSON, CSV (users/orders/files)।
- হোস্টিং প্যানেলে **ডেটা ব্যাকআপ/স্ন্যাপশট চালু রাখুন** (CodeNest ডেটা রিডিপ্লয়েও রাখে)।

### 🚨 নিরাপত্তা — এখনই করুন

1. **BotFather → `/mybots` → API Token → Revoke** করে নতুন টোকেন নিন — এবং নতুনটা
   **শুধু** `config.env` বা হোস্টিংয়ের Environment Variables-এ রাখুন, কোডে/README-তে নয়।
   (`config.env` যদি একবার রিপোতে চলে যায়, ফাইল মুছে দিলেও **পুরোনো কমিটে মানটা থেকে যায়** —
   তাই টোকেন বদলানো ছাড়া কোনো উপায় নেই। বট নিজেই এটা চিনে লগে ও অ্যাডমিনের DM-এ
   সতর্কবার্তা দেয় — `app/services/secrets_guard.py`।)
2. `/admin`-এর login password source code-এ আছে; public repo হলে সেটি গোপন থাকে না। Cookie-signing key database-এ randomভাবে তৈরি ও সংরক্ষিত হয়।
3. `/admin` পুরো স্টোর নিয়ন্ত্রণ করে — কখনো পাসওয়ার্ড ছাড়া পাবলিক রাখবেন না।

## 📡 চ্যানেলে অটো-পোস্ট (নতুন ভিডিও যোগ হলেই)

`/admin/settings` → 📣 ব্রডকাস্ট → **নতুন ভিডিও অটো-পোস্ট** চালু করে চ্যানেল বেছে দিন।
এরপর স্টোরে ভিডিও যোগ করলেই (বটে পাঠালে বা স্ক্যান করলে) চ্যানেলে চলে যায়:

- `AUTO_POST_TEXT` — পোস্টের লেখা, `{name}` = ফাইলের নাম
- `AUTO_POST_CHANNEL` — কোন চ্যানেলে (খালি রাখলে 📡 Channels-এর প্রথমটা)
- `AUTO_POST_LINK_LIMIT` — `0` = ভিডিও নিজেই যায়; `100` দিলে
  “🔓 ভিডিও নিন (১০০ বার)” বাটন যায় (ভিডিওটাই চ্যানেলে থাকে না, ক্লিক-লিমিট কাজ করে)
- সাথে ইনলাইন বাটন: “🟢 <স্টোর> খুলুন” (বট ইউজারনেম থেকে ডিপ-লিংক)

সব কাজ ব্যাকগ্রাউন্ডে হয় — আপনার আপলোড কোনোদিন অপেক্ষা করে না।

## 🌐 হোস্টিং প্যানেলের লাইভ লিঙ্ক (`/live/<job>`) — কেন কাজ করত না, কী ঠিক হলো

হোস্টিং প্যানেল (CodeNest/RunSpace, আর আপনার নিজের হোস্ট সাইট) জব চালানোর সময় ফাইলের
নাম ধরে entry point বেছে নেয়: `main.py → app.py → bot.py → server.py → index.py → run.py`।
এরপর দুটো জিনিস আশা করে:

1. `$PORT` পোর্টে (যেমন 11000) **লিসেন করা** — নইলে প্যানেল লেখে
   *“The job is running, but no web listener yet”*;
2. লিঙ্ক **`https://<panel>/live/<job>/`** আকারে দেখানো — অর্থাৎ অ্যাপকে
   `X-Forwarded-Prefix` মেনে চলতে হবে, নয়তো `/admin` বাটনে চাপ দিলে ইউজার প্যানেলের
   রুটে চলে যায় (404)।

আগে `bot.py`-এর ভিতরে ওয়েবসাইট চালানোর কোড ছিল **কিন্তু সেটা কখনো কল হত না**, আর
`WEB_ENABLED`-এর ডিফল্ট ছিল `false` — তাই জব “running” হয়েছিল কিন্তু কোনো পোর্ট খোলেনি।
এখন:

| Entry | কী করে |
|---|---|
| `main.py` (নতুন) | পুরো প্রোডাক্ট: সাইট + বট এক প্রসেসে; `$PORT` @ `0.0.0.0` |
| `bot.py` | `$PORT` থাকলে নিজেই `run.py`-তে যায় (বট রিট্রাই করে, সাইট কখনো ডাউন হয় না) |
| `run.py` | সাইট সবসময় চালু, বট কানেক্ট না হলে সাইট তবু চলবে |

- `WEB_ENABLED` ডিফল্ট **true**; হোস্টেড জবে (`$PORT` থাকলে) সাইট চালু হবেই — বন্ধ করা যায় না।
- প্রতিটা পেজে `<base href="/live/<job>/">` বসে আর লিঙ্কগুলো base-relative হয়, তাই
  মেনু, “বিস্তারিত”, ফর্ম ও ৩০৩ রিডাইরেক্ট সব লাইভ লিঙ্কের ভিতরেই থাকে।
- জানতে চাইলে: `curl http://127.0.0.1:$PORT/health` → `port`, `host`, `from_port_env`,
  `url_prefix` — এই চারটা দেখলেই বোঝা যায় প্যানেলের লিঙ্ক ঠিক আছে কি না।
- ডিপেন্ডেন্সি: প্যানেল **শুধু `requirements.txt`** ইনস্টল করে (রিপো মোডে `pip install -r
  requirements.txt`; import-স্ক্যান শুধু inline কোডের জন্য চলে)। তাই ওয়েব স্ট্যাক
  (`fastapi`, `uvicorn`, `python-multipart`) এখন `requirements.txt`-এই রাখা — আগে ওগুলো
  শুধু `requirements-web.txt`-এ ছিল, আর হোস্টেড জবে সাইটটাই চালু হত না।
- টেস্ট: `tests/test_web.py` আসল `python main.py` / `python bot.py` চালিয়ে `$PORT`
  খোলে কি না ও `/live/<job>/` প্রিফিক্স মানে কি না — দুটোই যাচাই করে।

> 💡 আপনার নিজের বানানো সাইট (group_moderator — `website-model-info` ফাইলটা) ঠিক এই
> প্যাটার্নেই চলে: `main.py`, `aiohttp`/`uvicorn` @ `0.0.0.0:$PORT`, আর পেজ থেকে
> হালকা (relative) পাথ দিয়ে `api/…` কল। আমরা এখন একই নিয়ম মেনে চলছি, তাই একই
> প্যানেলে দুটোই একসাথে চলে।

## 🔐 নিরাপত্তা পেজ (`/admin/security`)

রিপো পাবলিক, তাই প্যানেল নিজেই বারবার পরীক্ষা করে দেখায়: `config.env` কমিট হয়েছে কি না,
গিট ইতিহাসে টোকেন এখনো পড়া যায় কি না, আর **রিপোর কোনো ফাইলে সরাসরি লেখা টোকেন/হ্যাশ/সেশন**
আছে কি না (নমুনা লুকিয়ে দেখায়, “…” দিয়ে — এক লাইনেই বোঝা যায় কোন ফাইলের কোন লাইন)।
স্ক্যানার **গত কমিটেও** খোঁজে: ডিস্ক থেকে ফাইল মুছে দিলেও কমিট করা পর্যন্ত টোকেন সবাই পড়তে
পারে, তাই সেটাও ধরা পড়ে। পাশে ধাপে ধাপে ঠিক করার নিয়ম: BotFather →
Revoke → নতুন টোকেন শুধু Environment Variables-এ → পুরোনো সেশন Terminate।

## 🗑 একসাথে অনেক কিছু মুছুন (mass delete)

- **ফাইল**: 🗂 Files পেজে ID লিখে (বা বটে) একবারে অনেক ভিডিও মুছে ফেলা যায় — লিংক/ড্রিপ/
  ফেভারিটও পরিষ্কার হয়।
- **ইউজার**: 👥 Users পেজে টিক দিয়ে একসাথে অনেক ইউজার, অথবা 🧹 “পুরোনো ইউজার পরিষ্কার”
  দিয়ে “৯০ দিন অ্যাকটিভ না” / “কখনো শুরুই করেনি” ফিল্টার করে — আগে দেখায় কতজন যাবে,
  তারপর মোছে। অ্যাডমিন কখনো মুছবে না।

## ⏳ ভুল করে লেখা টেক্সট আর সেভ হবে না (প্রশ্নের সময়সীমা)

বট যখন আপনার কাছে কিছু জিজ্ঞেস করে (“চ্যানেলের লিংক দিন”, “কত ক্লিক?”), সেই প্রশ্ন
`FLOW_TIMEOUT_SECONDS` (ডিফল্ট **৬০০** = ১০ মিনিট) পর নিজে থেকেই বাতিল হয়ে যায়।
আগে প্রশ্নটা দিনের পর দিন সক্রিয় থাকত — তাই পরে আপনি যা-ই লিখতেন, সেটাই সেই
প্রশ্নের উত্তর হয়ে সেভ হয়ে যেত (একই জিনিস বারবার সেভ হওয়ার আসল কারণ)।

- প্রতিটি প্রশ্নের নিচে **✖️ বাতিল** বাটন থাকে — চাপলেই প্রশ্ন বাতিল, কিছুই সেভ হয় না।
- প্যানেলের অন্য যেকোনো বাটনে চাপ দিলেও সামনে থাকা প্রশ্নটা বাতিল হয়ে যায়।
- ভুল উত্তর পরপর **৩ বার** দিলে বট নিজেই বলে “বারবার ভুল হচ্ছে — কাজটি বাতিল করলাম”,
  তারপর প্রশ্নটা সরিয়ে দেয় (ভুল ডেটা জমতে পারে না)।
- সময় শেষ হয়ে গেলে বট স্পষ্ট করে জানায়: “⏳ আগের প্রশ্নটির সময় শেষ — কিছুই সেভ হয়নি”।
- ভ্যালুটা প্যানেল → ⚙️ Settings থেকেও বদলানো যায়; config.env-এ `FLOW_TIMEOUT_SECONDS`।

## 📊 দৈনিক রিপোর্ট (অ্যাডমিনকে নিজেই মেসেজ করে)

`OWNER_REPORT_ENABLED=true` (ডিফল্ট চালু) আর `OWNER_REPORT_HOUR=21` সেট থাকলে

## 🧪 নিজের কোড যাচাই করার টুল (`tools/`)

```bash
.venv/bin/python tools/static_check.py app web tools bot.py run.py   # undefined name
.venv/bin/python -m pytest tests -q                                  # ২৮১টি টেস্ট
DB_FILE=preview.sqlite3 .venv/bin/python tools/seed_demo.py          # ডেমো ডেটা
```

`static_check.py` হলো একটা ছোট “pyflakes” — ধরতে পারে `NameError` (যেমন ডিপ্লয়ে
ঘটে গিয়েছিল: `scheduler.start_all()` কিন্তু `scheduler` import করা ছিল না —
বট কানেক্ট হওয়ার সাথে সাথেই ক্র্যাশ)। টেস্ট-স্যুটেও চলা হয়, তাই এটা আর
কখনো ফিরে আসবে না। একইভাবে `tests/test_screens.py` **৫২টি বট স্ক্রিন** একবার
একবার করে রেন্ডার করে দেখে — কোনো বাটনে চাপ দিলে স্ক্রিন খুলবে কি না।
